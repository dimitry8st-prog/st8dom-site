# Сбор и очистка контента для портала ДИС

## Решение

Apify используется только как сборщик. Он не решает, можно ли доверять материалу,
и не передаёт результат напрямую в KnightCat. Между сбором и AI стоит
детерминированный шлюз очистки, а между AI и публикацией — редакционная и
медицинская проверка.

```text
Расписание → реестр разрешённых источников → API/RSS/sitemap/Apify
→ RAW-хранилище → очистка → карантин → дедупликация → оценка источника
→ KnightCat (только черновик) → проверка фактов → Степанов Д.А.
→ Telegram на согласование → портал + канал после одобрения
```

RAW-копия нужна для аудита, но никогда не вставляется в системный промпт и не
публикуется. Публичная «Библиотека ДИС» хранит только одобренные материалы;
Life-OS хранит источники, заметки, связи и черновики.

## 1. Реестр источников до запуска Apify

Для каждого домена хранить:

- владелец и тип: официальный орган, клиническая рекомендация, журнал, медиа;
- разрешённый способ: официальный API, RSS, sitemap или публичная HTML-страница;
- ссылка на условия использования и результат проверки `robots.txt`;
- допустимые разделы сайта и запрещённые пути;
- частота обновления и лимит запросов;
- язык, страна и медицинский контур: RU или INT;
- условия цитирования, лицензия и допустимость изображения/видео;
- ответственный за источник и дата последней проверки.

Источник без записи в реестре не запускается автоматически. Авторизация,
платный доступ, CAPTCHA и закрытые персональные данные не обходятся.

## 2. Как снизить риск блокировок

Порядок выбора способа сбора:

1. Официальный API или выгрузка — основной вариант.
2. RSS или sitemap — для обнаружения новых URL.
3. Обычный HTTP-запрос — для статических публичных страниц.
4. Браузерный Actor — только когда контент действительно формируется JavaScript.

Настройки для пилота на одном домене:

- `maxConcurrency: 1`; повышать только после наблюдения за ответами сервера;
- пауза 3–8 секунд со случайным отклонением между страницами;
- не более 100 новых страниц за один запуск и отдельный дневной бюджет;
- повторять только временные ошибки: 408, 425, 429 и 5xx;
- экспоненциальная пауза: 30 секунд, 2 минуты, 10 минут; максимум 3 повтора;
- при повторном 403, CAPTCHA или `Retry-After` — остановить домен и уведомить оператора;
- сохранять `ETag` и `Last-Modified`, повторно получать только изменившиеся страницы;
- использовать одну сессию для последовательного публичного просмотра, а не для обхода ограничений;
- прокси применять только там, где сбор разрешён и он нужен для устойчивости или нужной географии;
- не менять IP в попытке обойти явный запрет сайта.

Apify Academy отдельно рекомендует API-сбор как более устойчивый к изменениям
HTML, различает быстрый Cheerio/HTTP-подход и тяжёлый браузерный сбор, а также
описывает прокси, сессии, заголовки, fingerprints и повторы. Для портала эти
механизмы подчиняются правилам источника и стоп-условиям выше.

## 3. Очистка до AI

Модуль `content_cleaning.py` выполняет проверяемые операции без LLM:

1. принимает только полный URL `http(s)`;
2. удаляет `utm_*`, `fbclid`, `gclid`, якоря и другие метки слежения;
3. сверяет домен с белым списком;
4. удаляет HTML, скрипты, стили, SVG и невидимые Unicode-символы;
5. ограничивает размер текста до 50 000 символов;
6. считает SHA-256 URL и содержимого;
7. удаляет повторы по каноническому URL или хешу текста;
8. отправляет в карантин фрагменты, похожие на инструкции для модели;
9. отклоняет пустые, слишком короткие и структурно неверные записи.

Слова об «игнорировании инструкций» не вырезаются незаметно: материал получает
статус `quarantine`, чтобы человек мог увидеть причину. Это защищает KnightCat
от prompt injection внутри страницы или расшифровки видео.

Минимальная очищенная запись:

```json
{
  "status": "candidate",
  "title": "...",
  "canonical_url": "https://...",
  "source_domain": "...",
  "published_at": "2026-09-20",
  "clean_text": "...",
  "content_hash": "sha256",
  "url_hash": "sha256",
  "prompt_injection_markers": [],
  "rejection_reasons": []
}
```

## 4. Оценка медицинского источника

Перед генерацией черновика запись получает класс:

1. `A` — официальные клинические рекомендации и государственные органы;
2. `B` — систематические обзоры, руководства профессиональных обществ,
   рецензируемые статьи;
3. `C` — университеты, клиники и материалы специалистов с проверяемым авторством;
4. `D` — СМИ, блоги, социальные сети и ролики без достаточной методологии.

Материал класса `D` может подсказать тему, но не подтверждает медицинское
утверждение. Для каждого существенного утверждения KnightCat должен сохранить
ссылку, точную опору в источнике, дату публикации и уровень уверенности. При
расхождении источников черновик помечается для ручного разбора.

Российский и международный контуры не смешиваются. В российском материале
сначала проверяются действующие рекомендации Минздрава РФ; международные
документы можно использовать как отдельное сравнение с явной маркировкой.

## 5. Проверка видео ЛФК

До попадания ролика в видеотеку фиксируются:

- заболевание, этап восстановления и целевая функция;
- автор, квалификация и организация;
- дата выпуска и дата медицинской проверки;
- необходимые условия: помощь, опора, оборудование;
- противопоказания и критерии остановки занятия;
- варианты упрощения и усложнения;
- наличие понятной демонстрации и субтитров;
- первоисточники, лицензия и разрешение на встраивание;
- отсутствие обещаний «полного восстановления» и универсальных схем.

Ролик без описания безопасности не публикуется как практическая инструкция.
Он может остаться во внутренней очереди только как источник темы.

## 6. Узлы n8n

| Шаг | Узел | Результат |
| --- | --- | --- |
| 1 | Schedule Trigger | Запуск по расписанию |
| 2 | PostgreSQL: Source Registry | Только разрешённые источники |
| 3 | Split Out / Loop Over Items | Обработка доменов по одному |
| 4 | Apify Actor / HTTP Request | Сырые записи и технические метаданные |
| 5 | PostgreSQL: Raw Content | Неизменяемая RAW-копия с TTL |
| 6 | Code: Cleaning Gate | Канонический URL, чистый текст, флаги и хеши |
| 7 | IF: reject/quarantine | Остановка или ручная проверка |
| 8 | PostgreSQL: Upsert | Дедупликация и история версий |
| 9 | Source Scoring | Класс A–D и медицинский контур |
| 10 | KnightCat | Структурированный черновик со ссылками |
| 11 | Fact Check | Проверка опор и обязательных полей |
| 12 | Telegram approval | Одобрение или отклонение человеком |
| 13 | Portal import | Только `draft`; публикация отдельной кнопкой |

## 7. Метрики и стоп-условия пилота

- доля дублей;
- доля `reject` и `quarantine` с причинами;
- успешные ответы по доменам и частота 403/429;
- стоимость одного принятого источника;
- доля утверждений с проверяемой опорой;
- число медицинских правок до одобрения;
- время от обнаружения до готового черновика.

Стоп-условия: рост 403/429, изменение правил сайта, появление персональных
данных, потеря привязки утверждений к источникам или попытка публикации без
медицинской проверки.
