# MIT → портал → краткий отчёт в Notion

API предназначен для существующего workflow `Life-Os/n8n/lifeos-mit-rss-to-notion.json`.
Вся запись остаётся приватной в Life-OS. Автоматической публикации статей нет.

## Настройка

На сервере приложения установить случайный `LIFEOS_INGEST_TOKEN` длиной минимум
32 байта в окружении контейнера и пересоздать контейнер приложения. Пустой ключ
выключает API (503). В n8n создать Header Auth credential с именем заголовка
`Authorization` и значением `Bearer <ключ>`. Этот ключ не связан с паролем читателя.
Не сохранять ключ в GitHub, JSON workflow или сообщениях.

## Контракт

- `POST /api/life-os/mit/import/`: JSON `{"materials": [...]}`, максимум 100 записей.
  Каждая содержит `title`, `source_url`, `stream`, необязательные `summary`,
  `published_date`. Потоки: `science-ai`, `science-neuro`, `science-longevity`.
  Принимаются только HTTPS URL домена news.mit.edu. Сервер не загружает URL.
  Весь пакет проверяется до первой записи; одинаковые нормализованные URL
  возвращаются как existing. Каждый материал фиксируется отдельно: при сбое БД
  часть пакета может быть сохранена, безопасно повторить весь пакет.
- `GET /api/life-os/mit/pending/`: до 100 старейших материалов MIT без подтверждения
  Notion. Поля отчёта: id, title, report, portal_url. Полный текст не передаётся.
- `POST /api/life-os/mit/reports/<id>/ack/`: `{"notion_page_id": "UUID"}`.
  Повтор того же подтверждения безопасен, другой UUID даёт 409.

Все три запроса требуют Bearer credential, ответы не кешируются. Страницы
материалов и поиска сохраняют пароль Life-OS.

## Восстановление

Сбой Notion не удаляет материал. До ack он остаётся в pending независимо от того,
есть ли он ещё в RSS. После таймаута создания Notion сначала выполнить поиск
по точному portal_url, затем подтвердить существующую страницу. Не повторять
Create Notion Item автоматически вслепую. Ошибка сохраняется в n8n execution.
Отправку не запускать параллельно из нескольких workflow: Notion не обеспечивает
уникальность URL и атомарность query/create. Если найдены две страницы, поток
останавливается для ручного решения. Подтверждение ack доверяет выделенному
credential и не проверяет страницу через Notion API.

## Проверка запуска

1. Подключить два credentials в n8n: портал Header Auth и Notion API.
2. Импортировать обновлённый файл, оставить inactive.
3. Ручной запуск: сохранённые анонсы видны в научных потоках Life-OS.
4. Notion содержит только заголовок, короткий отчёт и ссылку на портал.
5. Повторный запуск не создаёт новых портальных записей и подтверждённых отчётов.
6. Смоделировать отказ Notion: материал остаётся pending; после восстановления
   поиск обнаруживает ранее созданный отчёт, ack убирает его из очереди.
7. После этих проверок активировать еженедельное расписание.

Анонс MIT News — новость, не автоматически проверенное научное исследование.
Авторская проверка первоисточника выполняется отдельно. DOI и смысловая
дедупликация остаются следующим этапом.
