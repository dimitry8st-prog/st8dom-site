# ДИС Монитор клинических рекомендаций

Модуль автоматически добавляет на портал библиографические карточки официальных
клинических рекомендаций по неврологии и нейрохирургии. Оригинальный документ
остаётся в официальном источнике; портал хранит название, организацию, дату,
версию, коды МКБ и ссылку.

## Российский контур

Источник: `https://cr.minzdrav.gov.ru/`.

Сервер получает действующие рекомендации из официального JSON-метода, оставляет
документы, одобренные Научно-практическим советом, и отбирает профильные записи
по названию, разработчикам и кодам МКБ. Повторный запуск не создаёт дубли:
ключом служит сочетание источника и `CodeVersion`.

Для каждой карточки отдельно вычисляется нормализованная связь с профилем
`neurology` и/или `neurosurgery`. Она хранится в таблице
`clinical_guideline_specialties` и используется фильтром каталога; общая строка
«Неврология / нейрохирургия» больше не считается достаточной классификацией.

### Автоматическая загрузка в GitHub и Obsidian

Workflow `.github/workflows/sync-clinical-guidelines.yml` запускается каждый
понедельник в 06:30 по Москве. Сетевые запросы выполняются на VPS портала:
15 ноября 2026 года соединение с GitHub runner завершалось тайм-аутом, а
тот же официальный API с VPS вернул действующие записи. Workflow проверяет реестр, обновляет
`data/clinical_guidelines.json` для карточек сайта и создаёт Markdown-заметки в
`obsidian-vault/Клинические рекомендации/Входящие/`. Коммит создаётся только при
реальном изменении данных; push запускает обычное обновление сайта.

В Obsidian нужно открыть папку `obsidian-vault` как Vault. Полный первичный
проход запускается вручную в GitHub Actions с параметром `full_sync`.

Сбор на VPS выполняется через SSH внутри уже работающего контейнера портала,
используя существующие секреты развёртывания. Страницы Минздрава читаются через
одну HTTP-сессию с повторным использованием соединения. Экспорт пишет только временные
файлы; БД портала, сценарии n8n и допуски RAG не меняются. JSON-снимок содержит
только библиографические метаданные успешных источников. GitHub проверяет его
формат и официальные домены, сливает карточки по источнику и внешнему ID, затем
сохраняет реестр и заметки. SSH-ключ удаляется после шага; полные тексты не передаются.
Для проверки доступности без записи есть ручной workflow
`Check medical source connectivity`.

### Временные сбои и неполный сбор

Минздрав и AAO-HNSF проверяются независимо. Тайм-ауты, ошибки подключения,
HTTP 429/500/502/503/504 повторяются не более трёх раз с паузами 1 и 2 секунды.
Ошибки доступа и некорректный формат не маскируются повторными запросами.
Если каталог AAO-HNSF больше не позволяет распознать отслеживаемый документ
и дату, это ошибка адаптера, а не успешный сбор нуля карточек.

Изменения Минздрава сливаются в реестр после успешной проверки всех
запрошенных страниц. При ошибке поздней страницы сохраняется прежняя версия
данных этого источника. Доступный международный источник всё равно проверяется
и сохраняется; аналогично российский результат сохраняется при отказе AAO-HNSF.
Старые карточки при недоступности источника не удаляются.

В GitHub Actions тесты выполняются до сетевого сбора. Отчёт по каждому
источнику находится в сводке запуска. При частичном сбое доступные обновления
сначала коммитятся и передаются на портал, затем задание завершается с ошибкой,
чтобы неполный сбор не выглядел успешным. Поля `sources`, `errors` и `ok`
доступны также в JSON-выводе команды; `--report-file PATH` сохраняет отчёт.

Этот workflow собирает библиографические карточки рекомендаций. Ежедневный
сбор MIT в Life-OS работает отдельно. Автоматический сбор PubMed и журналов
Lancet/Brain этим workflow не выполняется; поиск статей не следует принимать
за подтверждение работы такого парсера.

### Альтернативный запуск из n8n

1. `Schedule Trigger`: еженедельно, например в 06:30 по Москве.
2. `HTTP Request`: `POST https://st8dom.ru/api/clinical-guidelines/sync/minzdrav/?page=1&page_size=25`.
3. Заголовок: `Authorization: Bearer {{$env.GUIDELINES_SYNC_TOKEN}}`.
4. `IF`: проверить, что `ok = true`.
5. При ошибке отправить владельцу уведомление; при успехе записать статистику
   `scanned`, `matched`, `created`, `updated`, `unchanged`, `total_pages`.

Ежедневно достаточно проверять первую страницу: официальный API сортирует её от
новых документов к старым. Для первоначального наполнения n8n проходит страницы
от `1` до `total_pages` последовательными запросами. Маленькие страницы нужны,
потому что официальный сервер иногда медленно формирует большую выгрузку.

Одинаковое значение `GUIDELINES_SYNC_TOKEN` задаётся в окружении сайта и n8n.
Секрет нельзя хранить в workflow в открытом виде или коммитить в Git.

## Международный контур

AAO-HNSF подключён непосредственно к еженедельному GitHub Actions workflow.
Адаптер читает только официальный каталог `entnet.org`, распознаёт заранее
разрешённые профильные документы и добавляет их в общий реестр. Сейчас так
контролируется `Clinical Practice Guideline: Tinnitus Update` (2026). Если
верстка официального каталога изменится и дата перестанет распознаваться,
адаптер не создаёт карточку из догадки и не удаляет последнюю подтверждённую.

Остальные международные источники пока передают метаданные через n8n:

Адаптер источника в n8n получает метаданные с официальной страницы организации
и отправляет каждую карточку в:

`POST https://st8dom.ru/api/clinical-guidelines/import/`

Разрешённые источники: AAO-HNSF, AAN, EAN, ESO, CNS, AANS, NICE, WHO и AHA/ASA. Сервер
проверяет HTTPS и домен по белому списку; ссылка с постороннего домена будет
отклонена.

Пример пакета:

```json
{
  "source_key": "ean",
  "external_id": "ean-guideline-2026-001",
  "title": "Название клинической рекомендации",
  "organization": "European Academy of Neurology",
  "version": "2026",
  "codes": "G20",
  "specialties": "Neurology",
  "url": "https://www.ean.org/official-guideline-page",
  "published_on": "2026-09-17",
  "status": "active"
}
```

## Правила безопасности

- карточка с неофициального домена не принимается;
- повторный пакет обновляет существующую запись, а не создаёт дубль;
- PDF не копируется без подтверждённого права на распространение;
- AI не меняет текст официального документа;
- разбор доказательств и практические выводы публикуются только после проверки
  Степановым Д.А.;
- при недоступности источника старые карточки не удаляются автоматически.

## Проверка после развёртывания

1. Открыть `/clinical-guidelines/`.
2. Запустить российский workflow вручную.
3. Убедиться, что появились только профильные карточки и ссылки ведут на
   `cr.minzdrav.gov.ru`.
4. Повторить запуск и проверить, что `created = 0`, а записи не продублировались.
5. Перед включением расписания проверить уведомление об ошибке источника.
