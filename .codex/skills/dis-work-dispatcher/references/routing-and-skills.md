# Выбор режима и дополнительного skill

## Основной режим

| Режим | Использовать для | Не использовать как основной для |
| --- | --- | --- |
| ChatGPT | обсуждение идеи, объяснение, выбор направления, короткий текст, план | непосредственного изменения репозитория или длительного веб-процесса |
| ChatGPT Work | исследование, файлы, документы, таблицы, презентации, браузерные задачи, коннекторы, регулярные проверки | глубокого изменения кодовой базы с тестами и git-операциями |
| Codex | аудит репозитория, код, тесты, Docker, GitHub, исправления, деплой и проверка сайта | простой беседы, когда не нужны рабочая среда и инструменты |

Комбинируй режимы только когда это уменьшает риск или ручную работу. Типовая цепочка контент-завода: Work исследует и собирает доказательства, ChatGPT помогает принять редакционное решение, Codex публикует и проверяет портал.

## Как предлагать optional skill

1. Посмотри перечень реально доступных skills в текущей сессии.
2. Отбери не более трёх, которые существенно меняют качество результата.
3. Объясни пользу через результат, а не через внутреннее название инструмента.
4. Рекомендуй один вариант. Второй и третий должны быть реальными альтернативами, включая вариант «без дополнительного skill», когда он разумен.
5. Дождись выбора до подключения optional skill.

Примеры маршрутизации:

- Word/Google Docs с проверкой вёрстки → документный skill.
- Excel/CSV/Google Sheets, формулы и диаграммы → табличный skill.
- PDF с визуальной проверкой → PDF skill.
- Презентация → презентационный skill.
- Новая архитектура AI, RAG, агент или n8n → AI-архитектурный skill.
- Неясное клиентское ТЗ → skill проектирования клиентского решения.
- Ошибка Docker/API/TLS/интеграции → evidence-first диагностика.
- Текущее сравнение моделей OpenAI → официальный OpenAI docs skill.
- Продолжение прежнего проекта → personal-context, если актуального файла или репозитория недостаточно.
- Создание изображения → image generation skill.

## Обязательные исключения

Не задавай вопрос перед skill, когда:

- пользователь прямо назвал skill;
- системные правила требуют его для данного типа артефакта;
- без него нельзя корректно прочитать или создать требуемый формат;
- платформа явно предписывает его использование.

В этих случаях коротко объяви, какой skill используется и почему. Если skill требует отдельного решения, доступа или разрешения на внешнее действие, запроси только это разрешение.
